Lapisan Jaringan & Domain
🔍 Alamat Domain Tidak Ditemukan DNS_FAILED

Ibarat mencari nama seseorang di buku telepon tapi namanya tidak ada — sistem tidak bisa menemukan alamat dari nama domain yang dituju (misalnya kemhan.go.id). Biasanya karena domain kedaluwarsa, salah ketik URL, atau DNS server bermasalah.

📞

Yang perlu dilakukan: Hubungi Tim Jaringan / Pengelola Domain, lalu cek masa aktif domain dan ejaan URL di panel Admin.

🚫 Server Menolak Koneksi TCP_CONNECTION_REFUSED

Rumahnya ditemukan, tapi pintunya dikunci dari dalam — server hidup namun aplikasi web-nya (Nginx/Apache/IIS) tidak mau menerima koneksi masuk. Biasanya layanan web server mati atau diblokir firewall.

📞

Yang perlu dilakukan: Hubungi Sysadmin / Tim Server untuk mengecek apakah service web server berjalan dan aturan firewall-nya.

⏱️ Tidak Ada Respon Sama Sekali TCP_TIMEOUT

Dipanggil berkali-kali tapi tidak menjawab sampai waktu habis — server benar-benar bisu, tidak ada respon apapun. Kemungkinan server fisik mati, kabel data center terputus, atau sedang terkena serangan DDoS.

📞

Yang perlu dilakukan: Segera hubungi Tim Infrastruktur & Data Center untuk cek kondisi fisik server dan jalur ISP.

Lapisan Aplikasi & Server Web (Kode HTTP)
🚷 Error Klien — Akses Ditolak / Halaman Tidak Ditemukan HTTP_4XX

Server hidup dan merespon, tetapi menolak permintaan karena kesalahan di sisi permintaan itu sendiri — misalnya diblokir WAF (403), IP monitoring diblokir firewall, URL salah/halaman dihapus (404), atau sistem monitoring di-rate limit (429).

📞

Yang perlu dilakukan: Hubungi Tim Keamanan / Pengelola Konten Web, cek kode HTTP spesifik di kolom "Pesan Error", lalu verifikasi URL atau whitelist IP monitor.

💥 Error Server — Aplikasi Rusak / Kelebihan Beban HTTP_5XX

Server hidup dan bisa dihubungi, tapi ada masalah di dalam kode programnya sendiri — bagaikan kasir yang masuk kerja tapi mesinnya rusak dan tidak bisa melayani. Bisa berupa error kode program (500), proxy tidak bisa ke aplikasi (502), server kelebihan muatan (503), atau aplikasi terlalu lama merespon (504).

📞

Yang perlu dilakukan: Hubungi Tim Developer / Programmer Web untuk membuka log error aplikasi dan mengecek penggunaan RAM/CPU server.

🔄 Redirect Tak Terbatas (Loop) TOO_MANY_REDIRECTS

Server terus-menerus mengarahkan ke URL lain tanpa berhenti, membentuk lingkaran tidak berujung — sistem berhenti setelah 10 redirect agar tidak terjebak selamanya. Biasanya karena konfigurasi redirect di Nginx saling melingkar atau middleware CMS salah konfigurasi.

📞

Yang perlu dilakukan: Hubungi Sysadmin untuk memeriksa konfigurasi redirect di Nginx/Apache.

⚠️ Kesalahan HTTP Tidak Terkategori HTTP_ERROR

Terjadi kesalahan saat melakukan permintaan HTTP yang tidak termasuk kategori lainnya — bisa karena koneksi terputus di tengah proses atau error jaringan tingkat rendah yang tidak terklasifikasi.

📞

Yang perlu dilakukan: Hubungi Tim Developer untuk investigasi, cek log sistem monitoring untuk detail error.

Timeout & Respon Lambat
🐌 Halaman Terlalu Lama Merespon TIMEOUT

Server bisa dihubungi dan port terbuka, namun proses memuat halaman web memakan waktu melebihi batas yang ditetapkan (default: 5 detik). Biasanya tanda server sedang kewalahan — traffic tinggi, query database berat, atau RAM/CPU hampir habis.

📞

Yang perlu dilakukan: Hubungi Tim Sysadmin & Developer untuk memantau penggunaan CPU & RAM server.

Keamanan & Sertifikat SSL (Gembok HTTPS)
🔓 Sertifikat Keamanan Kedaluwarsa SSL_CERT_EXPIRED

"Gembok" keamanan HTTPS sudah melewati tanggal masa berlakunya. Browser modern (Chrome, Firefox) akan menampilkan peringatan merah besar kepada semua pengunjung dan memblokir akses publik.

⚠️

PRIORITAS TINGGI — Yang perlu dilakukan: SEGERA hubungi Tim Keamanan / Sysadmin untuk memperpanjang sertifikat SSL (Let's Encrypt/DigiCert) dan aktifkan auto-renewal agar tidak terulang.

🔐 Masalah Konfigurasi Sertifikat SSL SSL_ERROR

Sertifikat keamanannya ada dan belum expired, namun ada yang tidak beres — misalnya sertifikat yang dipasang bukan milik domain tersebut (hostname tidak cocok), atau menggunakan sertifikat self-signed.

📞

Yang perlu dilakukan: Hubungi Tim Sysadmin untuk menyesuaikan konfigurasi SSL di Nginx/Apache. Jika website internal, aktifkan "Abaikan SSL" di panel Admin.

⏳ Timeout Saat Negosiasi Enkripsi SSL SSL_TIMEOUT

Koneksi berhasil ke server, tetapi proses "jabat tangan" enkripsi SSL/TLS tidak selesai dalam batas waktu. Biasanya terjadi ketika server kelebihan beban atau ada masalah konfigurasi TLS.

📞

Yang perlu dilakukan: Hubungi Tim Sysadmin untuk memeriksa performa server dan mengoptimasi konfigurasi TLS.

Deteksi Keamanan Konten (Fitur Khusus SIPANTAU)
🚨 Indikasi Peretasan / Judi Online DEFACEMENT_DETECTED

Situs berhasil diakses (HTTP 200), namun isi konten halaman telah disusupi kata kunci judi online ("slot gacor", "sbobet") atau pesan peretas ("hacked by"). Sangat berbahaya bagi citra instansi pertahanan.

🚨

TINDAKAN DARURAT — Yang perlu dilakukan: SEGERA hubungi Tim CSIRT / Keamanan Siber Kemhan, isolasi web server dari internet publik, lalu restore backup aman & lakukan audit forensik.

🔎 Kata Kunci Wajib Tidak Ditemukan KEYWORD_MISSING

Situs merespon tapi tidak menampilkan kata kunci yang diharapkan (misalnya nama instansi). Menandakan aplikasi mengalami blank page putih, redirect ke halaman maintenance, atau template gagal merender.

📞

Yang perlu dilakukan: Hubungi Tim Developer Aplikasi untuk cek error log web server dan buka URL target secara manual di browser.

Lainnya
🔗 Format URL Tidak Valid INVALID_URL

URL yang dikonfigurasi di monitor tidak dapat diproses karena formatnya salah — harus diawali dengan https:// atau http://. Biasanya karena URL diinput tanpa protokol atau ada karakter tidak valid.

📞

Yang perlu dilakukan: Periksa dan perbaiki URL di panel Admin — pastikan lengkap, misalnya https://kemhan.go.id.

❓ Error Tidak Dikenal UNKNOWN_ERROR

Terjadi kesalahan yang tidak dapat dikategorikan oleh sistem. Bisa jadi error jaringan yang sangat tidak umum atau kondisi server yang tidak pernah diantisipasi sebelumnya.

📞

Yang perlu dilakukan: Hubungi Tim IT untuk investigasi dan cek log sistem monitoring SIPANTAU.

Catatan Sistem Monitoring

Sistem ini menggunakan mekanisme Retry (Coba Ulang) sebelum menetapkan status DOWN. Artinya, jika terjadi gangguan sesaat (kedip jaringan), sistem akan mencoba ulang 2–3 kali sebelum membunyikan alarm. Ini mencegah notifikasi "alarm palsu" akibat gangguan jaringan sementara.
